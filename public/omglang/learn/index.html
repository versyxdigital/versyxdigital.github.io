Learn OMG

A tour of the whole language, from the first line to closures and error handling. Every example is live: change it, press Run (or Ctrl Enter) and see what happens. Breaking things is the point.

01Hello, world

The smallest OMG program prints one line.

Three things to know before going further:

  • OMG files start with ;;;omg on the first line by convention. It is optional, but editors and tools use it to recognise the language.
  • emit prints a value, followed by a new line.
  • # starts a comment that runs to the end of the line. Longer comments go between /* and */.

02Variables

You introduce a new variable with alloc. You change one that already exists with := on its own.

The two are kept apart on purpose. Assigning to a name that was never introduced is an error, so a typo cannot quietly create a second variable. Run this one and read the message.

The rules in full:

  • Every new name needs alloc. Declaring the same name twice at the top level is an error.
  • A name declared inside a function is local to that function and invisible outside it.
  • A function can read and update a global with plain :=. To get a separate local that hides the global, use alloc again inside the function.

03Numbers and math

OMG has integers and floats. Integer math stays in integers, with one exception: / is true division and always gives a float. Use // when you want a whole number back.

Integers are 64-bit, and the bitwise operators work on them.

04Floats

A number with a decimal point or an exponent is a float.

That last line prints false. It is not a bug in OMG: floats are 64-bit IEEE-754 numbers, the same as in most languages, and 0.1 has no exact binary form.

The usual math functions are built in, and int and float convert between the two kinds.

05Strings

Strings go between double quotes. + joins them, and joining a string to a number converts the number for you.

Inside a string these escapes work: \n (new line), \t (tab), \r, \\, \" and \0. To get at individual characters as numbers, use ascii and chr.

06Booleans and comparisons

Anything can stand in for a condition. These count as false: false, 0, the empty string "", the empty list [] and the empty dictionary {}. Everything else counts as true.

07Conditionals

if picks a branch. elif is short for "else if": you can have as many as you like, and the final else is optional. Try a few scores.

08Loops

OMG has two kinds of loop. The first is loop, followed by a condition and a block. The block runs for as long as the condition holds, like while in other languages.

break leaves the innermost loop early.

continue skips the rest of the block and goes back to the condition.

The second kind is for, which walks through a list one item at a time, or through a string one character at a time. There is no counter to keep. break and continue work here too.

If you write a loop that never ends, nothing bad happens here. Press Stop, or wait: examples on this page are stopped after ten seconds.

09Lists

A list holds values in order. It can be indexed, sliced and changed in place.

Two variables can hold the same list. A change made through one is visible through the other, because there is only one list.

Lists and loops together cover most everyday work. This one adds up a list and finds its largest value.

10Dictionaries

A dictionary maps names to values. The keys are strings, and you can reach an entry with a dot (person.name) or with brackets (person["name"]). Brackets are the ones to use when the key is in a variable.

Entries keep the order they were added in. dict_keys gives you the keys as a list, and for over that list is how you walk a dictionary.

11Functions

proc, short for procedure, defines a function. return hands back a value.

A function can call itself. This is the classic recursive Fibonacci.

Functions are values

You can pass a function to another function, keep it in a variable, or return it.

Closures

A function defined inside another one remembers the variables around it, even after the outer function has returned. That is a closure. Each call to make_adder below makes a new add with its own n.

The inner function shares the variable itself, not a copy of its value. If it changes the variable, the change is still there on the next call. That is enough to build a counter with private state.

12Modules

A program can be split across files. Suppose this is saved as mathlib.omg:

mathlib.omg
;;;omg

alloc PI := 3.141592653589793

proc square(x) {
    return x * x
}

proc cube(x) {
    return x * x * x
}

Another file brings it in with import and gives it a name. The module's top-level proc and alloc definitions are then reached through that name.

The path in quotes is relative to the file doing the importing. A module is read and run once, however many times it is imported, and what it exports is read-only.

13Files

read_file reads a whole text file in one go, and gives false if it cannot. Say there is a file called notes.txt:

notes.txt
buy milk
fix the parser
call Sam

For more control, open a handle. The second argument is the mode: "r" to read, "w" to write and "a" to append. Add a b ("rb", "wb") to work with bytes instead of text, as a list of numbers from 0 to 255.

On this site, files live in memory and are gone when the program ends. Nothing touches your disk. On your own machine the same code reads and writes real files, relative to the folder you ran omg from.

14Errors

Things go wrong: a bad index, a missing key, a division by zero. When nothing handles the error, the program stops and prints a traceback that shows where it happened and how it got there.

To carry on instead, wrap the risky part in try and except. The name after except receives the error as a string.

Raise an error of your own with panic.

facts states something that must be true. If it is, nothing happens. If it is not, the program stops with an AssertionError. It is a simple way to write tests.

15Built-in functions

These are always available, with nothing to import.

Strings and characters
length(x)Length of a string or a list, or the number of entries in a dictionary.
chr(n)The one-character string for the number n.
ascii(c)The number for a one-character string.
string_bytes(s)The UTF-8 bytes of s, as a list of integers.
bytes_to_string(bytes)The reverse: a list of bytes to a string.
Numbers
int(x), float(x)Convert between the two kinds of number, or parse one from a string.
floor(x), ceil(x)Round a float down or up to an integer.
round(x)Round to the nearest integer. Ties go to the even one.
abs(x)Absolute value.
sqrt(x), pow(a, b), log(x)Square root, power, natural logarithm.
sin(x), cos(x), tan(x)Trigonometry, in radians.
hex(n)Lower-case hexadecimal text for an integer.
binary(n), binary(n, w)Binary text. With a width, the low w bits, padded with zeros.
Lists
append(list, item)Add item to the end of list, in place.
list_repeat(item, n)A new list holding item n times.
Dictionaries
dict_keys(d)The keys, in the order they were added.
has_key(d, k)Whether d has the key k.
freeze(d)A read-only version of a dictionary.
Files
read_file(path)The whole file as text, or false.
file_open(path, mode)Open a file and return a handle.
file_read(h), file_write(h, data)Read what is left, or write, through a handle.
file_close(h)Close a handle. Written data is saved at this point.
file_exists(path), is_dir(path)Ask about a path.
read_dir(path), make_dir(path)List a folder, or create one.
Time and errors
time_ms()The current time in milliseconds. Useful for timing things.
sleep_ms(n)Pause for n milliseconds.
panic(msg)Raise an error that try can catch.
exit(code)End the program with a status code.

Every program can also read three variables: args, the command-line arguments as a list of strings; module_file, the path of the running script; and current_dir, the folder omg was run from.

A few more exist for programs that run in a terminal: reading the keyboard and standard input, and starting other programs. They need a real terminal, so they do nothing useful on this site. The README lists them all.
